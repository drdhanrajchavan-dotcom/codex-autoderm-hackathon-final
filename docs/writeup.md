# Methodology Writeup

AutoDerm was built as a Codex-native clinical research system, not as a conventional hand-coded model demo. The operator, a practicing dermatologist, specified the clinical problem: acne severity grading on Indian and darker skin, with five scored lesion classes, a safety-critical nodule/cyst recall constraint, and a fixed split that the model could not negotiate. Codex wrote the training code from that clinical specification, then improved its own code through an autoresearch loop. The human role was domain definition and clinical judgment; the Codex role was implementation, experiment execution, and code mutation.

The methodological contribution is the held-out-primary keep rule. Earlier autoresearch loops can overfit a small research validation set, especially when every mutation is rewarded for looking better on the same small split. AutoDerm fixes that failure mode in code. Each Codex mutation edits only `src/train.py`; `run_experiment` trains the candidate, evaluates both `research_val` and `locked_eval`, writes an immutable `experiment_row.json`, and appends `results.tsv`. `keep_rule` only keeps a mutation if locked_eval does not regress beyond the tolerance, one of the improvement thresholds is met, nodule/cyst recall remains at least 0.50, and no locked_eval class precision drops by more than 0.10 absolute. When research_val and locked_eval disagree, locked_eval wins.

That rule matters clinically. Acne labels are small, imbalanced, and noisy. A candidate that boosts aggregate validation mAP by overcalling inflammatory lesions can look attractive on a small validation set while becoming unsafe for real patients. The locked evaluation set acts as the primary clinical signal, while research_val remains the early-stopping and secondary corroboration signal.

The system architecture supports that separation. Code and the demo app run on the M5 Max laptop, while heavier training and mutation evaluation run on EC2. Kept rows, diffs, prompts, and weights are pulled back locally, but promotion remains manual through `config/active_checkpoint.json`. That keeps model selection auditable and prevents a live demo from silently changing underneath the clinician.

The clinical differentiator is darker skin. The dataset is predominantly Fitzpatrick type IV-VI Indian skin, where erythema, pigmentation, and post-inflammatory changes can have lower visible contrast than in lighter-skin benchmark examples. AutoDerm treats performance on darker skin types as a first-class metric. The best discovered loop insight was clinically interpretable: the kept iteration preserved small-lesion detail by moving to 768px training images, reducing destructive color/value augmentation, lowering mosaic/mixup/erasing, and increasing nodule/cyst sampling. In plain terms, Codex learned that "more augmentation" was not always better; on melanin-rich skin, aggressive color shifts can wash out subtle lesion contrast.

The workflow ROI is direct. Manual lesion counting takes 3-4 minutes per image. AutoDerm returns per-lesion boxes, counts, and a severity badge in about 2 seconds. That turns severity grading from an occasional manual measurement into something that can happen at every visit.

The long-term clinical vision is treatment outcome tracking at scale. If every consultation automatically produces standardized lesion labels, counts, and severity, then before/after response can be measured across thousands of patients instead of a few manually audited cases. That makes routine care data usable for research publications, comparative treatment evaluation, and more evidence-based dermatology.
